title: Droid
description: Use Factory's droid CLI as an agent in Arakun. Install it, sign in, pick a model and see what your Factory plan has left.

Arakun runs Droid through Factory's `droid` CLI, in its own JSON-RPC mode. No adapter or Node.js is needed.

## What you need

The `droid` CLI, from [factory.ai](https://factory.ai). Arakun looks for it on your `PATH` and in `~/.local/bin`. Set `ARAKUN_DROID_BIN` to use another binary.

## Sign in

Run `droid` in a terminal and sign in, or press <kbd>Ctrl+K</kbd> and pick **Sign in to Droid**, which opens a terminal that runs it. Sessions use droid's own login. When it expires, droid renews it itself. To sign out, sign out on Factory's side.

## See your plan

Settings › Droid › Plan usage opens the Factory account dialog. Arakun reads your plan's limits with droid's login, `FACTORY_API_KEY`, or a Factory API key you connect there:

<Steps>

<Step>

### Create a key

In Factory, open Settings › API Keys and create one.

</Step>

<Step>

### Connect it

Paste the key in the dialog and click **Connect**. Arakun keeps it in the system keyring and only uses it to read usage. It sends it only to api.factory.ai.

</Step>

</Steps>

## Pick a model

The menu next to the composer lists the models droid offers, with each one's credit multiplier, such as ×2. Models your plan can't use show why. Each model has its own reasoning levels.

Two more settings sit there:

- **Autonomy:** what Droid may do without asking. **Ask first** reads freely and asks before any edit or command. **Low** edits files. **Medium** also runs reversible commands, like installs and builds. **High** runs any command, pushes and deploys included.
- **Mode:** **Normal** works on the task straight away. **Spec** writes a plan first and waits for your approval.

A new session starts with the defaults in `sessionDefaultSettings` in `~/.factory/settings.json`.

## Usage

The Usage tab reads token use and Factory credits from Droid's own logs in `~/.factory/sessions`. With your plan connected, it shows the 5-hour, weekly and monthly windows of the pool you use, Standard or Core, and any extra usage balance. The session footer shows tokens, credits and how full the context is. Arakun sends a desktop notification at 80% and when a limit is reached.

## What does not work yet

- No fast mode.
- `arakun agent new` can't start a Droid session, and [headless agents](/docs/headless-agents) can't run Droid.
- Arakun doesn't change your overage setting. When your Standard usage runs out, pick Droid Core or Extra Usage in Factory.

## Common errors

<Accordions>

<Accordion title="droid was not found on PATH or in ~/.local/bin">

Install Factory's CLI, or point `ARAKUN_DROID_BIN` at the binary.

</Accordion>

<Accordion title="Droid is not signed in">

Click **Sign in in a terminal** under the error, or run `droid` in a terminal and sign in. Then retry.

</Accordion>

<Accordion title="Stopped: your Factory usage for this model is exhausted">

Your plan has no room left for this model. Pick a cheaper model, switch to Droid Core or Extra Usage in Factory, or use Claude Code: the composer offers the switch.

</Accordion>

<Accordion title="Factory rejected the API key">

The key in the Factory account dialog no longer works. Create a new one and connect it, or click **Disconnect** to read limits with droid's login.

</Accordion>

</Accordions>
