---
title: Server
description: Run Arakun without a window on a build box, an office workstation or a VPS, and follow its agent sessions from your other devices.
---

`arakun server serve` is Arakun without a window: for a build box, the workstation at the office or a VPS. It runs sessions of any agent signed in on that machine and keeps them going while nothing is connected.

`arakun-server` is the same server as a program of its own. It needs no display library.

<Callout type="tip">
  Sign in to each agent on that machine first. The server uses its logins and its permission settings.
</Callout>

## Set it up

<Steps>
<Step>

### Start it

```sh
arakun-server serve   # runs until Ctrl+C
```

</Step>
<Step>

### Pair a device

In another terminal:

```sh
arakun-server pair    # a link and its QR code
```

The link is good for two minutes and pairs one device. Use it in one of two ways:

- In the app: open the Servers tab and paste the link.
- On a phone, or in any browser: open the link.

</Step>
<Step>

### Work with sessions

```sh
arakun-server add ~/code/app                 # a folder sessions can start in
arakun-server new --agent claude "fix the failing test"
arakun-server ls                             # folders and sessions
arakun-server wait <id>                      # until it stops working
arakun-server send <id> <text>               # a follow-up
arakun-server approve <id>                   # or deny
```

</Step>
</Steps>

## How devices reach it

<Tabs items={['relay', 'tailscale', 'lan']}>
<Tab value="relay">

`--reach relay` is the default. The server dials out, so it works behind a firewall, and everything between the device and the server is end-to-end encrypted.

</Tab>
<Tab value="tailscale">

`--reach tailscale` serves it at the machine's tailnet name over HTTPS.

</Tab>
<Tab value="lan">

`--reach lan` listens over plain HTTP.

<Callout type="error">
  Nothing is encrypted. Use it only on a network you trust.
</Callout>

</Tab>
</Tabs>
