## Turn tabs on

Open Arakun › Extensions, or Settings › General › Sidebar. Besides Inbox, Runs, Branches and Marketplace, you can turn on:

GitHub, Notes, Memory, Usage, Cloudflare, PostHog, Linear, Doop, Isometric, Phone, Computers and Automations.

The palette and Customize › Sidebar list only the tabs that are on. Every tab that is on and has no row of its own in the sidebar is in **More views**, a row that opens them in a menu by name, with their counts. A new install starts with none on, except what you set up on first launch: GitHub once the GitHub CLI is signed in, and Phone if you paired one. The choice is kept in `extensions.json` next to the state.

## Usage

Token use and estimated API cost, from Claude Code's and Droid's own logs and Devin's local session history. Sessions run outside Arakun count too. Models without a known API price show as unpriced, not as free.

It also shows the plan limits of Claude Code, Droid, OpenCode and Devin. Arakun has no account of its own. It reads the limits with the sign-in each CLI already has, and **Sign in** runs the CLI's own login. It sends that sign-in only to the provider's own host, over https.

<Accordion title="Claude Code on CLIProxyAPI">

Add the proxy's management key in the tab to see the 5-hour and weekly limits of every Claude and Codex account behind it, and which ones the proxy holds back. For a proxy Claude Code does not run on, use **Add CLIProxyAPI** and type its address. The key is only sent to the proxy it was added for, over https or to this machine.

</Accordion>

### Where tokens go

Under Breakdown, **Where tokens go** reads the Claude Code transcripts on this computer (`~/.claude/projects`) and shows what makes sessions large:

- the setup that loads with every message (skills, plugins, MCP servers, `CLAUDE.md` files, hook output), and which of it no session called,
- each project's first-message size,
- how full sessions got,
- the noisiest tool results.

It lists what to fix first, largest first, with one suggestion each. Each finding has a button that opens the file, or the Marketplace tab's installed MCP servers, plugins or skills, where you change it. Every number is an estimate, at about 4 bytes a token. Arakun only reads the files: nothing is sent anywhere and your setup is not changed.

From a terminal, `arakun usage where` shows the same. The last 30 days count by default; `--days N` changes that (`--days 0` for all), and `--json` prints JSON.

## Claude seats

With several Claude subscriptions, give each Claude Code session a seat of its own, so parallel sessions don't drain one.

<Steps>
<Step title="Get a long-lived token">

Run `claude setup-token` for each subscription.

</Step>
<Step title="Save it as a seat">

```sh
arakun seat add work < token.txt
```

The token is read from stdin and checked with one small call. It is kept in the system keyring, with an empty `~/.local/share/arakun/seats/work` that lists the seat. A token an older Arakun saved in that file moves to the keyring the first time it is read.

</Step>
</Steps>

Each new Claude Code session then starts on the seat with the most room in its 5-hour window that is not near its 5-hour or weekly limit, and keeps that seat for its whole life. The composer shows the session's seat, and the Usage tab every seat's windows.

```sh
arakun seat ls        # the seats and their 5-hour and weekly usage
arakun seat rm work   # forget a seat
```

<Warning>
Seats can't work while `~/.claude/settings.json` sets `CLAUDE_CODE_OAUTH_TOKEN` in its `env` block, or while Claude Code runs on an API key, a gateway or a cloud provider. Sessions in the sandbox don't use seats either.
</Warning>

## PostHog

Add a personal API key. The tab matches your projects by their `phc_` keys and has Overview, Events, People, Flags, Experiments, Errors and Ask.

- **Fix with agent** on an error, and **Set up with agent**, put a prompt in the composer without sending it.
- **Ask** sends a question to PostHog AI, not to your coding agent, and shows the answer and the SQL behind it.
- Changing a flag or an experiment always asks you to type the flag key first.

The key needs `user:read`, `organization:read`, `project:read`, `query:read`, `feature_flag:read`, `experiment:read` and `error_tracking:read`. A view whose scope is missing says which one.

## Cloudflare

Uses the `cf` CLI's sign-in. Its pages show as tabs across the top of the view.

## Linear

The open [Linear](https://linear.app) issues assigned to you, grouped by state (in progress, todo, backlog) with their identifier, title, team and priority, and a search box over them. The tab opens without a project.

Sign in with a personal API key, from Linear › Settings › Security & access › Personal API keys. Read access is enough. Add one sign-in per workspace; the header switches between them. The keys are kept in the system keyring and go to Linear's API. Who signed in is kept in `~/.local/share/arakun/linear/sessions.json` (`%LOCALAPPDATA%\arakun\linear\sessions.json` on Windows).

The tab reads the list again when it is 5 minutes old or you refresh, at most every 30 seconds. When Linear's request limit is hit, it waits as long as Linear asks and says how many minutes are left.

Click an issue, or use <kbd>↑</kbd>/<kbd>↓</kbd> and <kbd>Enter</kbd>, to open it with its description and comments. <kbd>/</kbd> goes to the search box.

- **Work on it with agent** starts an agent session in the open project with the issue's identifier, title, description, comments and link. It leaves git and Linear to you: the agent is asked not to commit, push, open a pull request or touch the issue.
- **Open in Linear** opens the issue in a browser tab, or in your browser when no project is open.

## Doop

The canvases of a [Doop](https://doop.design) instance and the frames of the one you pick, page by page. A click opens the frame on the canvas in a browser tab. Sign in with the browser, or paste an agent key.

Accounts › Agents adds Doop's MCP server to Claude Code or Droid, so sessions can read and draw on the same canvases.

## Marketplace

Plugins, MCP servers and skills to add, and what the agents load now. The page has one layout for every agent: **Show for** in its header (All agents, Claude Code, Droid) changes only what the cells say.

- **Installed** lists each item once. Its Agents column shows which agents have it, such as "Off for Droid" or "Claude Code only". With one agent picked, an item that agent can't use stays in the list as "Not for Droid", with the reason.
- An item's details have an Agents card: one row per agent with the file it reads and, where Arakun can change it, a switch that turns the item off for that agent only.
- **Discover** installs for Claude Code. Each item has one card, which ends with **Install** or the item's state: Ready, Needs sign-in, Needs approval, Off, or Broken with the reason. The details pane says the same and holds the fix.
- Discover › MCP servers also lists Arakun's own picks, such as Linear, Notion and Sentry. A server found both there and in the MCP Registry, or added under another name for the same URL, shows once.

Discover › Skills searches [skills.sh](https://skills.sh). **Install** copies the skill into `~/.claude/skills`, where Claude Code and Workers AI find it.

A repository with several skills is a package. A skill's details list the other skills in its repository, with **Install all**. Type `owner/repo` or a GitHub link in the search box to list the skills of that repository, also one skills.sh does not know. Skills you already have stay as they are.

When a plugin or MCP server you installed still needs you to sign in before Claude can use it, its card and its details in Discover show **Sign in**. It opens your browser once, and Claude keeps the sign-in fresh after that.

The Marketplace's pages show as tabs across the top of the view.

**Where**, in an item's details, picks who Install sets it up for on this computer. Each choice shows the file it writes:

- **Everyone in &lt;project&gt;:** the repo's committed `.mcp.json`, `.claude/settings.json` or `.claude/skills`, for everyone who clones it.
- **Just me, in &lt;project&gt;:** Claude Code's `local` scope: `~/.claude.json` for an MCP server, `.claude/settings.local.json` for a plugin. A skill has no such choice.
- **Me, in every project:** your user, in `~/.claude.json`, `~/.claude/settings.json` or `~/.claude/skills`.

The Install button, its tooltip and the notice after it name the same place. With a paired server picked under **Install on**, the item goes on that server for every project there, and a skill can't be installed.

An MCP server that signs in gets the repo in its name when you install it in a repo, such as `github-acme-web` in acme/web, so each repo has its own sign-in. Paired servers get what you install here too. See [Server](/server).

## Isometric

Animated isometric scenes: the project's `iso/*.rhai` scripts, then the starters that ship with Arakun.

- **New scene** asks what to draw and starts a session that writes it in `iso/`.
- **Change** starts a session that edits the scene on screen.
- **Export PNG**, **Export SVG** and **Export animated SVG** save the scene.

Agents read the guide with `arakun iso docs`.

## Automations

Scheduled shell commands or agent prompts, per project. You can also make one from a sentence in the [palette](/the-palette).
