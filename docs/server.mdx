---
title: Server
description: Run Arakun without a window on a build box, an office workstation or a VPS, and follow its agent sessions from your other devices.
---

`arakun server serve` is Arakun without a window: for a build box, the workstation at the office or a VPS. It runs sessions of any agent signed in on that machine and keeps them going while nothing is connected. Agents ask for permission as they do in the app, and you answer from wherever you are.

`arakun-server` is the same server as a program of its own. It needs no display library.

<Tip>
Sign in to each agent on that machine first. The server uses its logins and its permission settings: an agent set to allow everything there asks for nothing here either.
</Tip>

## Set it up

<Steps>
<Step title="Install it">

On Linux (x86_64 or arm64), install `arakun-server` alone:

```sh
curl -fsSL {{installServerUrl}} | sh
```

It puts the binary in `~/.local/bin`. It checks the release's checksums, and their signature when a verifier is installed.

It also installs what the server runs agents with, if it is missing:

- git and gh, with the system's package manager. That needs root or `sudo` without a password; otherwise it prints the command to run.
- Node.js 22, in `~/.local/share/arakun/node`, linked as `node`, `npm` and `npx` in `~/.local/bin`. Without Node, a new session fails as it starts.
- Claude Code, in `~/.local/bin/claude`, when there is no `claude` on the `PATH`. Run `claude` once to sign in.

`--no-tools` leaves all four to you. `--version` installs a given release.

On a Mac or Windows, [install the app](/install) and use `arakun server` in place of `arakun-server`.

</Step>
<Step title="Sign in">

Through the relay (the default), the server needs a sign-in to your account:

```sh
arakun-server login   # once: sign in with GitHub, for the relay
```

`login` prints a code and `https://github.com/login/device`. Open that address on any device, enter the code and approve. The terminal says "Signed in as" and your login. The machine needs no browser.

Over Tailscale or the local network (`--reach tailscale` or `--reach lan`), no account is needed. Skip this step.

</Step>
<Step title="Start it">

```sh
arakun-server serve   # runs until Ctrl+C, a signal or `arakun-server quit`
```

Through the relay without a sign-in, `serve` in a terminal stops and says to run `login`.

</Step>
<Step title="Reach it from a device">

Through the relay, there is no link. Devices signed in to the same GitHub account get in:

- In the app: sign in with GitHub, then open the Computers tab. The server joins the list under **Your servers** by itself.
- On a phone, or in any browser: open `https://app.arakun.dev`, sign in as the same account and pick the server. It is the page the [phone remote](/phone-remote) uses: it lists the sessions, reads them live, and notifies you when one finishes or needs you.

`arakun-server pair` says the same.

Over Tailscale or the local network, run `arakun-server pair` in another terminal. It prints a link and its QR code. The link is good for two minutes and pairs one device. In the app's Computers tab, press **Add a computer**, pick **By link** and paste it. Or open it on a phone or in any browser.

</Step>
<Step title="Work with sessions">

```sh
arakun-server add ~/code/app                 # a folder sessions can start in
arakun-server new --agent claude "fix the failing test"   # prints its id
arakun-server ls                             # folders and sessions
arakun-server log <id>                       # its status and last entries
arakun-server wait <id>                      # until it stops working
arakun-server send <id> <text>               # a follow-up
arakun-server approve <id>                   # or deny: answer what it asks
arakun-server stop <id>                      # stop its turn
arakun-server devices                        # paired devices
arakun-server unpair <device>                # forget one
arakun-server machines                       # the account's machines, this one marked
arakun-server forget <label>                 # remove one of them from the account
```

`arakun-server help` lists them all.

</Step>
</Steps>

## The sign-in

- `login` again checks that the sign-in still works and says who is signed in. `login --force` signs in again and ends the old sign-in.
- `logout` ends the sign-in. A running server stays up and leaves the relay. Devices on the network or Tailscale stay.
- `status` shows who it is signed in as, "Not signed in", or that the sign-in ended.
- A sign-in lasts at most 180 days, or 90 days without use. Run `arakun-server login` again then.
- `forget <label>` disconnects a running machine. It stays out until it is restarted or signed in again with `login`.

<Note>
A server paired through the relay before v0.19.0 must sign in: run `arakun-server login` on it once. A device paired with a link through the relay must sign in too.

In the Computers tab, such a server says it was paired by link before 0.19. Sign in in the app and run `arakun-server login` on the server with the same GitHub account, or pair it again over Tailscale.
</Note>

## Agents

Claude Code, Droid, OpenCode, Codex, Devin, Cursor, Antigravity and Workers AI, as in the app.

Claude Code and Codex also need their ACP adapter. The server installs a missing one with npm the first time a session needs it, so Node 22 or newer must be on the server's `PATH`. The install script puts one there.

## In the app

Once connected, the app connects to the server when it starts. Each folder the server offers is an environment in the sidebar, marked with the machine's name. A folder whose repository you also have here (the same `origin`) joins that project. An environment whose folder you remove on the server yourself, such as with `rm` or `git worktree remove`, leaves the list with its sessions within a few seconds, unless a session there is still working or waiting for an answer.

Its sessions open in the same tabs, with the same composer, as sessions here. Send, stop, approve and answer go to the server. In a server's environment:

- The model menu lists the models and reasoning levels that server offers.
- A terminal is a shell in that folder on the server. The project commands from Settings run there too.
- The Changes panel shows that folder's changes. Stage, discard, commit, pull, push and the pull request button run there, with the server's `git` and `gh` logins.
- The Explorer lists its files, and they open in file tabs (text only). `@` in the composer completes its paths.
- Fork, compact, rewind and `/stage` run on the server. "Continue with" hands the session to another agent on that server.
- When an agent there needs a login, token or password, it asks with the same [private card](/start-a-session#when-the-agent-needs-a-secret) as in the app, and the phone page shows it too. What you type goes only over an encrypted connection: the relay, Tailscale or https. Over `--reach lan`, the card offers only **Decline**. A sandboxed agent on a server doesn't get the card yet.
- When the agent is not signed in on that server, the session shows a card with **Sign in in a terminal**. It runs the agent's sign-in in a terminal on the server.

"New environment" makes a worktree on a server too: <kbd>Alt</kbd>+click the **+** and pick the machine, or right-click a server's environment. It goes in `~/arakun-workspaces/<project>/<branch>` there.

To spread new environments across machines, turn on **Spread new environments** at the foot of the Computers tab's list. A new environment then goes to the least busy connected machine that has the project, this computer included. Set each machine to Prefer, Normal, Avoid or Off under **New environments** in its settings there. A preferred machine takes new environments before the others. An avoided one takes them only when no other can. One that is Off never takes them this way, but you can still pick it in the New environment dialog. When every machine is Off, a new environment goes to the open environment's machine.

To add a folder on a server, pick it in the Computers tab and press **Add a folder**. Clone runs that machine's git, with its logins. You can also paste a clone URL in Add project (<kbd>Ctrl+O</kbd>) and pick the item that clones it on the server, such as **Clone owner/app on box**. The new folder opens in its project once the server has it. If the clone fails, a notice says so. In the Marketplace, "Install on" adds a plugin or MCP server for Claude Code on a paired server.

Every paired server also mirrors this computer. When it connects, and after each install here, it adds the plugins (and their marketplaces), the user MCP servers and the skills from skills.sh it lacks. A notice lists what was added. What you installed in a repo just for you goes to the server's folders with the same `origin`. What you shared with the repo goes with git. The mirror never removes anything you installed.

- Over plain http, only plugins and skills go.

Your MCP sign-ins (Claude Code's tokens for the MCP servers you signed in to) go only to a server you let have them. Pairing by link asks, and the answer is no unless you change it. **Copy MCP sign-ins** in the server's settings in the Computers tab changes it later, and the server's card says when it holds a copy.

- Turning it off takes the copy off the server when it next connects. So does removing the server, or unpairing this app on it.
- A server paired before pairing asked keeps getting them until you turn it off.
- A server on macOS doesn't take sign-ins, since Claude keeps them in the Keychain there.

<Tip>
Set `ARAKUN_GITHUB=readonly` on the server, before `service install`, to keep it from pushing or opening pull requests.
</Tip>

## The Computers tab

The Computers tab lists this computer first, then your servers, each with its status as a dot and a word: Online, Connecting, Offline or Not connected. Pick one to see how it is reached, its environments and their sessions, its agents and their plan limits, and its settings. A session opens in its project.

Signed in, a server on your account joins the list by itself. Signed out, the list says your account's servers show up once you sign in. **Add a computer** shows both ways to add one: **Your own server**, signed in with your GitHub account, or **By link**, for one on Tailscale or your network.

**Remove**, in a server's settings or its ⋯ menu, asks once. Then the server forgets the app, and a server on your account leaves the account too. Its sessions stay on it. If the server can't be reached then, remove the app there with `arakun-server unpair <device>`.

### Cloud environments

Under the servers, **Cloud** offers a cloud environment: a server Arakun runs for you, so sessions keep working with your computer off. Access is given by hand. Press **Ask for access** there and say what you would use it for. The section then shows where your request stands.

With access, **New cloud environment** makes one. The first start takes a few minutes. The section shows whether it is awake, why it stopped and the hours left this month, with **Wake**, **Stop** and **Remove**. The phone's Computers screen has the same.

To let a cloud environment clone your private repositories and push branches, install the Arakun Cloud GitHub App on the repositories you choose, or on your whole account. Your own GitHub account must also be able to read the repository, and write to it for a push. No GitHub token is stored in the environment: Arakun adds a short-lived token for the one repository on each `git` request.

- Public repositories clone without the app.
- When git is refused, it prints why, with the link to install the app where it is missing.
- `git@github.com:` URLs work too. Git uses https for them.
- The `gh` CLI and Git LFS don't get a token yet.

## Keep it running

`service install` runs `serve --service` as a service: systemd on Linux, launchd on macOS. It starts the server now, again after a crash, and at boot (Linux) or login (macOS).

```sh
arakun-server login               # through the relay: sign in, before or after install
arakun-server service install     # takes serve's flags: --reach, --port, --relay
arakun-server service status      # installed, running, lingering, and how it is reached
arakun-server service logs -f     # what it prints
arakun-server service uninstall   # stop it and remove the service; the data stays
```

`arakun-server quit` stops it until the next boot or login. `service install --print` shows the service file and installs nothing.

- **Not signed in.** Through the relay, a service with no sign-in does not fail. It runs signed out, and connects as soon as you run `arakun-server login`, with no restart. A service installed before v0.19.0 needs only `arakun-server login` once after updating.
- **Logged out (Linux).** It keeps running after you log out, so you can set it up over SSH. If turning that on needs root, it prints the `sudo` command to run.
- **As root.** Many VPSs only have root. There it installs a system unit that runs as root. The binary must then be in a folder only root can write to, such as `/usr/local/bin`, not a home folder. To run the agents as another user, log in as that user and install from there.
- **macOS.** Use `arakun server service install`. It runs from login to logout, so a Mac nobody sits at needs automatic login.
- **Agents.** The service gets the `PATH` of the shell you install it from, so it finds the same agents. If Node comes from mise or nvm, install it from a shell where `node` works. If you install an agent somewhere else later, run `service install` again.

On Windows there is no `service` command yet. To keep the server running, start `arakun server serve --service` from Task Scheduler, with the trigger "At log on".

### Update it

The server does not update itself. Run the install line again, then restart the service on the new binary:

```sh
systemctl --user restart arakun-server
```

- Installed as root: the service is a system unit, so leave out `--user`.
- A server in another folder (`ARAKUN_SERVER_DIR`): its unit is `arakun-server-<folder>`.

## How devices reach it

<Tabs>
<Tab title="relay">

`--reach relay` is the default. The server dials out, so it works behind a firewall, and everything between the device and the server is end-to-end encrypted. `--relay <url>` names a relay of your own.

It needs `login`, before or after it starts. It lets in the devices signed in to the same account, with nothing to pair.

</Tab>
<Tab title="tailscale">

`--reach tailscale` serves it at the machine's tailnet name over HTTPS. It takes the machine's HTTPS port on the tailnet, so the app's Phone tab on Tailscale can't use it on the same machine.

</Tab>
<Tab title="lan">

`--reach lan` listens on every interface over plain HTTP, on port 7474 unless you pass `--port`.

<Danger>
Nothing is encrypted, including diffs, commit messages and pull request text. Use it only on a network you trust.
</Danger>

</Tab>
</Tabs>

What `serve` is started with is kept for the next run.

## What it keeps

The server keeps its data in `~/.local/share/arakun/server/`, which only your user can read: paired devices, the sign-in (`account.json`, which `logout` removes), folders, sessions and their transcripts, and photos sent with prompts. Photos sent with prompts are removed after 30 days, and the transcript of a session the server no longer lists after 7 days. The app's own files are not touched, so the app and a server can run side by side. `ARAKUN_SERVER_DIR` names another folder, for a second server on the same machine.

A turn that is running when the server stops is cut off. Its session is still there after a restart, and the next message picks it up.
